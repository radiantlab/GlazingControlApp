# 0001. Halio is the source of truth for panels

In production the Halio controller, not our database, defines which panels and groups exist and what tint each panel is at. `HalioAdapter` lists Halio v3 windows as panels and Halio groups as groups, reads each window's live tint on every panel listing, and sends tint commands to the controller; the only structure it adds there is any missing single-window group. Group create, edit, and delete are refused outside development, so production groups are managed on the controller itself. The local `audit.db` records every command in the audit log and the last level we commanded, but it never overrides what Halio reports. We chose this because the controller is what actually drives the glass: during bring-up the controller's responses did not always match the commands we sent, so a locally assumed tint could silently drift from the real one, while reading live state keeps the display honest and keeps working if the glass changes tint at a different speed. The cost is that panel and group views depend on the controller being reachable, so every Halio failure must be logged and shown rather than replaced with cached or guessed values; in development the panel simulator stands in for the controller.
