# 0004. Production and development never share a data directory

The production `audit.db` holds research history that cannot be recreated, so development must never be able to read from or write to it by accident. `SVC_ENVIRONMENT` is required and has no default, and the two environments get disjoint storage: development defaults to `svc/config/development` for configuration and `svc/.runtime/development` for data, and development Compose uses its own named volume, so neither touches the historical `svc/data` directory. Production has no defaults at all; it refuses to start unless `SVC_DATA_DIR` and `SVC_CONFIG_DIR` are set explicitly, and production Compose requires the absolute host directory in `SVC_PRODUCTION_DATA_DIR` rather than falling back to a development path. In every environment the data and configuration directories must not overlap, configuration is mounted read-only, and tests pin `SVC_ENVIRONMENT=development`. We accept the extra setup this requires, including a preflight script and several required variables in production, in exchange for configuration mistakes failing loudly at startup instead of silently mixing simulated and real records. See `DEV-SETUP.md`.
