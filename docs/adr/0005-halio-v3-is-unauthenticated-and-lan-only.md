# 0005. Halio v3 is unauthenticated and LAN-only

The service talks to the Halio controller through the v3 API served on the controller's admin console port (8083, under `/api/v3`). That API takes no credentials and is reachable only from the Halio network, the LAN-only trailer network the controller is on (the trailer's other network does not reach it); the legacy key-based API on port 8084 no longer accepts connections. Production therefore needs only `HALIO_API_URL` and `HALIO_SITE_ID`, while `HALIO_API_KEY` stays optional and is sent as `X-API-Key` only to a controller that still asks for one. We chose to rely on network isolation rather than add an authentication layer the vendor does not provide, and we do not bypass or modify the vendor's controller to change that. As a consequence, anything on the Halio network can command the glass, so the controller must stay off untrusted networks, its address and site ID belong only in ignored local configuration, and the service cannot be pointed at Halio from outside the trailer. Should the vendor reintroduce authentication on v3, the optional key path is where to resume, and this decision should be revisited.
